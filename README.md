# FlyBrain — робот-муха на Raspberry Pi Pico з реальним мозком дрозофіли

Фізична версія [DesktopFly](https://github.com/DenisSergeevitch/desktop-fly) на мікроконтролері.
Сервоприводом керує не умова `if (dist < 20)`, а симуляція **реального ланцюга мозку мухи**
з конектома FlyWire (FAFB v783): **668 нейронів і 18 968 синапсів** з реальними знаковими вагами.

```
HC-SR04 ──> LC4 / LPLC2 (314 детекторів насування) ──> DNp01 Giant Fiber ──> серво: стрибок-втеча
                     │                                     ▲
                     └──> 287 проміжних нейронів ──────────┘ (збудження + гальмування із затримкою 4 мс)
                                                  ──> MDN / DNg11 / DNp09 ──> задкування / грумінг / ходьба
```

## Залізо

| Компонент | Примітка |
|---|---|
| Raspberry Pi Pico (RP2040) | Pico W і Pico 2 теж підійдуть |
| HC-SR04 | ультразвуковий далекомір, «око» мухи |
| Сервопривід SG90 / MG90S | «лапка»: втеча, ходьба, грумінг |
| Резистори 1 кОм і 2 кОм | дільник для Echo (5 В → 3.3 В) |
| Конденсатор 470–1000 мкФ | на живлення серво (бажано) |

### Схема підключення

| Від | До Pico |
|---|---|
| HC-SR04 VCC | VBUS (пін 40, 5 В від USB) |
| HC-SR04 GND | GND (пін 38) |
| HC-SR04 Trig | GP2 (пін 4) — напряму |
| HC-SR04 Echo | **1 кОм → GP3 (пін 5)**, і від GP3 **2 кОм → GND** |
| Серво сигнал (жовтий/помаранчевий) | GP4 (пін 6) |
| Серво + (червоний) | VBUS (5 В) |
| Серво − (коричневий) | GND |

> ⚠️ Echo без дільника подає 5 В на GP3 і може пошкодити Pico.
> Якщо серво смикає Pico в перезавантаження — поставте конденсатор 470 мкФ між VBUS і GND біля серво
> або живіть серво від окремого 5 В (зі спільною землею).

## Встановлення

1. **Arduino IDE** → *Файл → Параметри → Додаткові URL менеджера плат*:
   `https://github.com/earlephilhower/arduino-pico/releases/download/global/package_rp2040_index.json`
2. *Інструменти → Плата → Менеджер плат* → встановіть **Raspberry Pi Pico/RP2040/RP2350** (Earle Philhower).
   Бібліотека `Servo` вже входить у це ядро.
3. Відкрийте `FlyBrain/FlyBrain.ino`, плата **Raspberry Pi Pico**, завантажте.
4. *Serial Monitor*, 115200 бод, режим «Новий рядок».

`FlyBrain/connectome.h` уже згенеровано, Python для старту не потрібен.

## Що відбувається

- **Ядро 0** рахує мозок рівно 1000 кроків на секунду (модель Leaky Integrate-and-Fire, τ = 20 мс,
  поріг 1.0, рефрактерність 2 мс, гальмівні синапси із затримкою 4 мс, шум, базові струми).
  Математика у фіксованій комі Q14, бо RP2040 не має FPU.
- **Ядро 1** опитує HC-SR04 (на перериваннях, без блокуючого `pulseIn`), рахує сигнал «насування»
  і керує серво, світлодіодом і Serial.

**Насування** (як `computeLoom()` в DesktopFly): що швидше об'єкт наближається відносно відстані, то
сильніший струм іде на LC4/LPLC2. Рука, що повільно зависла поруч (< 15 см), лише тривожить муху
(тремтіння), але не дотягує до порогу втечі. Різкий рух до датчика → детектори насування стріляють →
через ~4 мс спрацьовує Giant Fiber → **серво робить ривок, блимає світлодіод**.

Поведінка з частот командних нейронів (пороги з `SignalBuilder` оригіналу):

| Нейрони | Умова | Серво |
|---|---|---|
| DNp01 (Giant Fiber) | спайк | ривок на 170° на 150 мс, потім 0.8 с «відновлення» |
| MDN | > 8 Гц | лапка відведена назад і гребе (задкування) |
| DNg11 | > 8 Гц | дрібна швидка вібрація (грумінг) |
| DNp09 | > 3 Гц | розмах ∝ частоті (ходьба) |
| LC4/LPLC2 | частота / 80 | тремтіння у спокої (нервовість) |

Без жодних подразників муха живе своїм життям: шум і власна активність мережі час від часу
запускають ходьбу чи грумінг.

### Команди в Serial Monitor («оптогенетика»)

| Команда | Дія |
|---|---|
| `g` | стимулювати Giant Fiber → втеча |
| `m` | MDN 1 с → задкування |
| `c` | DNg11 1 с → грумінг |
| `w` | DNp09 1 с → ходьба |
| `a` / `d` | DNa01/02 лівої / правої півкулі |
| `l` | тест насування 0.6 |
| `p` | потік повітря → сенсорні нейрони |
| `s` | вимкнути/увімкнути потік статусу |

Рядок статусу показує частоти груп (Гц на нейрон), лічильник спайків GF і час кроку мозку
(має бути помітно менше 1000 мкс).

## Налаштування

Усі константи — на початку `FlyBrain.ino`:
- `LOOM_REL_FULL` — менше значення = муха лякливіша;
- `HOVER_NEAR_CM`, `HOVER_MAX` — реакція на руку, що просто зависла поруч (не піднімайте `HOVER_MAX`
  вище ~0.3, інакше муха постійно тікатиме);
- `REST_ANGLE`, `ESCAPE_ANGLE`, `ESCAPE_HOLD_MS` — під вашу механіку.

## Перевірка на комп'ютері

Ядро `fly_brain.h` не залежить від Arduino — той самий код перевіряється на ПК:

```sh
cd tools
g++ -O2 -std=c++17 -I../FlyBrain host_test.cpp -o host_test && ./host_test
```

Тест повторює інваріанти з `simtest.js` DesktopFly. Результати збігаються з оригінальною
JS-реалізацією:

| | оригінал (JS, float) | FlyBrain (Q14) |
|---|---|---|
| популяція у спокої | 5.21 Гц | 5.18 Гц |
| GF у спокої 4 с | 0 спайків | 0 спайків |
| LC при насуванні | 179.7 Гц | 180.0 Гц |
| затримка GF після насування | 4 мс | 4 мс |

## Перегенерація конектома

```sh
python3 tools/convert_circuit.py              # завантажить data/circuit.json з GitHub
python3 tools/convert_circuit.py --input circuit.json
```

Тільки стандартна бібліотека Python. Скрипт будує CSR-граф (зберігаються лише реальні зв'язки),
масштабує ваги як в оригіналі (`синапси × 0.0008`, LC4/LPLC2/сенсорні → GF × 6 як електричні синапси)
і переводить усе в Q14.

## Розвиток

- **Друге «око»**: другий HC-SR04 → окремо `brain.loomL` і `brain.loomR`; тоді запрацює кермування
  через DNa01/DNa02 (різниця `rateDNaL − rateDNaR`) — можна поставити два колеса чи дві лапки.
- **Більше лапок**: локомоторний ланцюг MaleCNS (1 045 нейронів, `data/locomotor_circuit.json` у
  DesktopFly) — для нього вже краще ESP32-S3 з PSRAM або Pico 2 (RP2350 має FPU).
